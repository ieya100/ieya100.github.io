# ASUS ROG STRIX X870-I — BIOS против 96 ГБ DDR5

### Как обновление BIOS превратило рабочую систему в стенд диагностики — и почему пришлось возвращаться к 1022

**Статус:** загрузка Windows восстановлена после отката на BIOS 1022. Длительные стресс-тесты памяти ещё не завершены.

## Конфигурация

| Компонент | Модель |
|---|---|
| Материнская плата | ASUS ROG STRIX X870-I GAMING WIFI |
| Процессор | AMD Ryzen 9 9900X |
| ОЗУ | KINGBANK KFXB, 96 ГБ (2×48 ГБ), DDR5-6400 CL32 |
| Тайминги EXPO | 32-39-39-99 |
| Видеокарта | NVIDIA GeForce RTX 4090 |
| SSD | Samsung 990 PRO 4 ТБ + 2 ТБ |
| Диагностика | ROG STRIX HIVE II Q-LED, HWiNFO64 |

До обновления **BIOS 1022** система долго работала без замеченных проблем: оба модуля, EXPO, DDR5-6400. До экспериментов с UCLK память работала с MCLK 3200 МГц и UCLK 1600 МГц (1:2), SoC около 1,25 В.

## Что произошло

После штатного обновления **1022 → 1805** плата зависла на **жёлтом индикаторе DRAM** в ROG STRIX HIVE II. Длительное ожидание, повторные запуски и установка одной планки не дали устойчивой загрузки. При отдельных успешных попытках POST Windows выдавала разные ошибки:

- `0xc0000221` — ошибка загрузки образа драйвера;
- `0xFC` — ATTEMPTED_EXECUTE_OF_NOEXECUTE_MEMORY;
- `0x7F` — UNEXPECTED_KERNEL_MODE_TRAP.

Проблемы наблюдались даже при **DDR5-4800, EXPO Disabled**. По этим сообщениям нельзя установить, повреждены ли файлы Windows: все они возникали во время нестабильной инициализации оборудования.

## Перебор версий BIOS

| BIOS | Наблюдение |
|---|---|
| **1022 до обновления** | 96 ГБ DDR5-6400 работали без замеченных проблем |
| **1805** | Зависания DRAM Q-LED, проблемы с POST и загрузкой Windows |
| **1805 повторно через FlashBack** | Проблема сохранилась |
| **1686 (beta)** | POST с одной 48-ГБ планкой; с двумя не удалось; наблюдалась ошибка отрисовки UEFI |
| **1681** | Windows загрузилась с одной планкой на 4800; две планки прошли POST после эксперимента с VDD/VDDQ 1,20 В; EXPO не дал надёжного запуска |
| **1022 через FlashBack** | BIOS видит 96 ГБ; после сброса и включения EXPO Windows загрузилась на 6400 |

Откаты выполнялись через **USB BIOS FlashBack**, на FAT32-флешке с файлом `A5573.CAP`. Несмотря на предупреждения ASUS о запрете отката, **на данном экземпляре платы возврат с 1805 на 1022 удался**. Это не гарантия для других плат и будущих прошивок.

После восстановления 1022 удалось вручную задать **UCLK = MEMCLK**: HWiNFO64 показал **MCLK 3200 МГц / UCLK 3200 МГц (1:1)**, SoC около 1,25 В. Успешный запуск ещё не является доказательством долговременной стабильности на 6400 1:1.

## Что могло измениться

В промежуточных выпусках ASUS упоминала изменения совместимости JEDEC, тренировки высокочастотной DDR5, поддержку новых EXPO-профилей и обновления AMD AGESA. В 1805 заявлены дополнительные улучшения производительности памяти и совместимости с чипами CXMT.

**Гипотеза:** регрессия затрагивает автоматическую тренировку памяти или подбор параметров контроллера (напряжения, ODT, drive strength, сигнальные задержки), а не обязательно сами DRAM-чипы. KINGBANK указывает SK hynix M-die для соответствующего комплекта, поэтому упоминание CXMT в описании 1805 не является прямым объяснением.

Зависание на JEDEC 4800 при успешном EXPO 6400 не доказывает деградацию ОЗУ: EXPO меняет одновременно тайминги, напряжения, режимы инициализации и другие параметры. При диагностике мы также меняли версии BIOS, число установленных модулей и DRAM VDD/VDDQ; строго изолировать одно исправляющее действие не удалось.

## Вывод

Конфигурация, работавшая до обновления, снова загрузилась после возврата **BIOS 1022**. Это указывает на возможную **регрессию прошивки или совместимости конкретной связки Ryzen 9 9900X + ASUS X870-I + 2×48 ГБ KINGBANK**, но не доказывает единственную первопричину.

Следующий контрольный этап — MemTest86 / OCCT, проверка WHEA и серии холодных стартов. Пока результаты этих тестов не получены, объявлять DDR5-6400 1:1 полностью стабильным преждевременно.

**Пожелание ASUS:** сравнить результаты тренировки 2×48 ГБ DDR5-6400 между BIOS 1022 и 1805 и дать возможность проверять совместимость без риска потерять рабочую конфигурацию.
